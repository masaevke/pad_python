# Задание 3. Нашел такой баг в проекте pgmpy

## Пример из открытого проекта

Проект: [pgmpy](https://github.com/pgmpy/pgmpy) - библиотека для работы с вероятностными графическими моделями.

Ссылка на строку кода: [pgmpy/sampling/Sampling.py#L252](https://github.com/pgmpy/pgmpy/blob/dev/pgmpy/sampling/Sampling.py#L252).

В файле `Sampling.py` у методов `BayesianModelSampling.rejection_sample` и `BayesianModelSampling.likelihood_weighted_sample` используется изменяемый аргумент по умолчанию:

```python
evidence=[],
```

Это антипаттерн из семинара: список создаётся один раз при определении функции и используется во всех вызовах, где аргумент не передан. Если изменить этот список, изменения сохранятся между вызовами.

Ветка `dev` меняется, поэтому номер строки по ссылке может со временем сместиться; нужное место можно найти по `evidence=[]` в сигнатуре метода.

## Как проявляется ошибка

Ниже показано два примерных случая использования списка как значение по умолчания или его изменения — это просто псевдопример механизма ошибки, а не фрагмент реализации pgmpy:

```python
def f(evidence=[]):
    evidence.append("x")
    return evidence


print(f())  # ['x']
print(f())  # ['x', 'x']
```

Оба вызова изменяют один и тот же список, поэтому второй вызов получает результат первого.

## Исправление

Вместо изменяемого значения по умолчанию используется `None`, а новый список создаётся внутри функции:

```python
def f(evidence=None):
    if evidence is None:
        evidence = []
    evidence.append("x")
    return evidence


print(f())  # ['x']
print(f())  # ['x']
```

Теперь каждый вызов без аргумента получает отдельный список.
